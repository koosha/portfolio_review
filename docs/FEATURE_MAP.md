# Portfolio Review capability preservation map

This map connects the existing Yahoo collector, the supplied `portfolio_lab_project` reference and `CODEX_HANDOFF_README.md` to the integrated application. It records source inspection, not investment validation. The reference's original files remain separate; its numerical modules and meaningful regression tests were adapted into the application.

**Verification state:** backend, collector, state and real-HTTP/in-memory-DOM tests passed. Chrome refused the local synthetic URL with `ERR_BLOCKED_BY_CLIENT`, so real rendering, responsive dimensions, native keyboard/focus and browser download checks remain blocked. See [Verification](VERIFICATION.md). A test named below establishes the listed software property, not live data completeness or investment validity.

## One application and shared context

`portfolio/server.py` serves one local Portfolio Review shell in `static/index.html`. `static/app.js` retains collection behavior and `static/research.js` supplies research presentation inside that shell. There is no iframe or separate research dashboard. `portfolio_lab/web.py` delegates to the integrated server as a compatibility entry point.

The primary destinations are Overview, Holdings, Research, Scenarios and Review; Data and Settings are utilities. A saved run, account display filter, valuation date, decision cutoff and mode are shared in the research toolbar. The account filter changes table display only; it does not silently change calculation denominators or permissions. Collection checkboxes remain the explicit choice of accounts to pull.

Data includes a table of eligible retained fund disclosures and their source references. |

## Synthetic fixture review

`tests/test_methodology.py` imports only the generated `fixture`, `sample`, `company` and `extract` test helpers. It uses synthetic security/account IDs, invented monetary values, mocked covariance/stress calculations and deterministic dates. It contains no personal holdings, local user paths, credentials, API keys or pairing material. It is suitable for source control. It is included in the reviewed source set.

Detailed numerical before/after behavior is in `METHODOLOGY_GAPS.md`; real collector semantics are in `SOURCE_SCHEMA.md`; operational commands and final verification belong to the main README and operating documentation.
